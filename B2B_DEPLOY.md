# Выкат корпоративной версии на rodnoygolos.ru

Обе версии живут в одном репозитории и собираются из одного кода.
Отличает их переменная `VITE_EDITION`.

```
VITE_EDITION=b2c  →  rodnyegolosa.ru   lk/dist      (как сейчас)
VITE_EDITION=b2b  →  rodnoygolos.ru    lk/dist-b2b
```

Папки сборки разные намеренно: при одинаковых вторая сборка затирала бы
первую, и на один из доменов уезжал бы чужой кабинет.

Лендинги — точки входа одной сборки: `index.html`, `b2b.html`,
`constructor.html` и `privacy.html`. У корпоративного своя таблица
стилей (`src/scss/b2b.scss`) и свой скрипт (`src/js/b2b/`) — с B2C он
не делит ничего, кроме шрифта.

---

## 1. Сборка на сервере

Корпоративная версия собирается одной командой, и она **не трогает
«Родные голоса»**:

```bash
cd /var/www/rodnyegolosa.ru/mumisnearby
git pull origin main
npm install
npm run build:b2b
```

Что при этом происходит:

| Что | Состояние после сборки |
|---|---|
| `dist/b2b.html` | пересобран, наши правки |
| `lk/dist-b2b/` | пересобран, кабинет компаний |
| `dist/lk/` | **не пересобирался** — вернулся тот же, что был |
| `dist/index.html` | перегенерирован, содержимое не изменилось |

Про последнюю строку. Лендинги — одна сборка vite с несколькими
точками входа, разделить их нельзя: `vite build` делает их вместе и
чистит перед этим всю папку `dist`. Поэтому `scripts/build-b2b.mjs`
прячет готовый кабинет B2C во временную папку и возвращает его на
место как есть. Содержимое `index.html` при этом не меняется — может
смениться только хеш в имени общего CSS-файла.

Когда нужно выкатить именно B2C — обычная команда, как раньше:

```bash
npm run build
```

## 2. nginx

Готовый файл лежит в репозитории: `deploy/nginx-rodnoygolos.ru.conf`.

**Вставлять его в терминал руками нельзя**: zsh экранирует точку с
запятой после URL, и `proxy_pass` ломается молча — `nginx -t` при этом
проходит.

```bash
cp deploy/nginx-rodnoygolos.ru.conf /etc/nginx/sites-available/rodnoygolos.ru
ln -s /etc/nginx/sites-available/rodnoygolos.ru /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
```

### Три ловушки, на которые уже наступали

**Одного симлинка мало.** В `nginx.conf` этого сервера подключён не
`sites-enabled/*`, а конкретный файл по имени. Рядом с
`include /etc/nginx/sites-enabled/rodnyegolosa.ru;` нужна вторая
строка с `rodnoygolos.ru`. Без неё конфиг не читается вовсе, а запросы
уходят в блок старого домена и получают 301 на его https.

**Регулярное `location` сильнее префиксного.** Кеширующее правило для
статики перебивало `location /lk/`, и на корпоративный домен уезжал
B2C-бандл — белый экран. Поэтому в конфиге стоит `location ^~ /lk/`.

**Список проксируемых префиксов должен быть полным.** Корень отдаёт
статику, так что всё, чего нет в списке, до бэкенда не доходит и
возвращает html со статусом 200. Для формы заявки это худший случай:
она отрапортует об успехе, а заявка никуда не уйдёт. Сейчас в списке:
`api`, `auth`, `voices`, `generations`, `subscription`, `support`,
`admin`, `super_admin`, `companies`, `leads`, `notifications`,
`referral`, `profile`.

## 3. SSL

```bash
certbot --nginx -d rodnoygolos.ru -d www.rodnoygolos.ru --non-interactive --agree-tos --redirect
```

Certbot дописывает редирект и блок на 443 **прямо в
`/etc/nginx/sites-available/rodnoygolos.ru`**. Поэтому повторное
копирование конфига из репозитория стирает SSL, и после каждого `cp`
нужно снова прогнать эту же команду: сертификат уже выпущен, certbot
просто переустановит его.

## 4. Проверить после выката

| Что | Адрес | Ожидаемо |
|---|---|---|
| Лендинг | `rodnoygolos.ru` | корпоративные тексты, нет «Конструктора» и программы лояльности |
| Вход компании | `/lk/#/company/login` | форма входа по email |
| Кабинет компании | `/lk/#/company/dashboard` | слоты и статистика |
| Сотрудники | `/lk/#/company/staff` | список, добавление, смена тарифа |
| Админка юрлиц | `/lk/#/admin/companies` | список компаний, создание пакета |
| Кабинет сотрудника | `/lk/#/subscription/tariff` | тариф только для чтения, без оплаты |
| Политика | `/privacy.html` | открывается, не 404 |
| Старый домен | `rodnyegolosa.ru` | ничего не изменилось |

Последняя строка — главная: B2C-сборка от этих правок не меняется, и
это стоит проверить глазами до того, как объявлять релиз.

## 5. Чего на бэкенде нет

- **`POST /leads`** — форма заявки шлёт сюда. Пока ручки нет, форма
  честно показывает ошибку отправки. Заявки с лендинга не доходят
  никуда, это надо закрыть до продвижения домена.
- **`company_id` в `GET /auth/who_am_i`** — сотрудника приходится
  узнавать по 403 на создание платежа. Работает, но криво.
- Самостоятельной регистрации компаний нет: юрлицо заводит
  администратор в `/admin/companies`. Поэтому кнопки лендинга ведут на
  форму заявки, а не в ЛК, хотя в ТЗ написано «Зарегистрировать
  компанию».
